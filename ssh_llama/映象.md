 Docker 的「映像（Image）」可以理解成一份用來建立容器的完整範本。

  你剛才執行：

  docker pull ollama/ollama

  就是把 Ollama 的映像下載到 Vultr 主機。接著：

  docker run ... ollama/ollama

  Docker 便使用這份映像建立並啟動 Ollama 容器。

  可以用「食譜與餐點」來理解：

  Docker 映像（Image）＝準備好的食譜與食材包
  Docker 容器（Container）＝依照食譜做出並正在使用的餐點

  更精確的關係是：

  ollama/ollama 映像
         │
         │ docker run
         ▼
  名為 ollama 的容器
         │
         └── 執行 Ollama 服務

  映像與容器有幾個重要差別：

   映像                      容器
  ━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   建立容器的範本            映像執行後的實例
  ────────────────────────  ──────────────────────────────
   通常是唯讀的              執行期間可以產生資料
  ────────────────────────  ──────────────────────────────
   不會自己運行              有啟動、停止及重新啟動等狀態
  ────────────────────────  ──────────────────────────────
   一份映像可建立多個容器    每個容器彼此獨立

  以目前環境為例：

  - ollama/ollama：Docker 映像。
  - ollama：我們建立的容器名稱。
  - gemma4:e2b：Ollama 管理的 AI 模型，不是 Ollama 容器本身。
  - Docker Volume ollama：保存模型資料的位置。

  整體結構如下：

  Vultr Ubuntu
  └── Docker
      ├── ollama/ollama 映像
      ├── ollama 容器
      │   └── Ollama 程式正在運行
      └── ollama Volume
          └── Gemma 4 模型檔案

  映像也常被翻譯成「映像檔」或「映像」。在 Docker 的語境中，通常寫作「Docker 映像」。
