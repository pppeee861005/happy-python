可以把 Skill 想成食譜，把模型想成廚師。

小模型：剛學做菜的新手

小模型像一位剛進廚房的學徒。

你不能只跟他說：

幫我煮一鍋好吃的牛肉湯。

因為他可能會：

忘記先退冰
不知道牛肉要不要汆燙
水放太多
鹽下太早
火開太大
煮到一半不知道怎麼判斷熟了沒有

所以要給他很詳細的食譜：

1. 牛肉切成 3 公分大小。
2. 冷水下鍋汆燙 3 分鐘。
3. 撈出後用清水洗淨。
4. 鍋中加入 1500 ml 水。
5. 放入牛肉、薑片與蔥。
6. 大火煮滾後轉小火。
7. 煮 90 分鐘。
8. 最後 10 分鐘才加鹽。
9. 確認牛肉能用筷子穿透。

甚至還要準備好工具：

切肉腳本
汆燙腳本
計時腳本
測溫腳本
調味腳本

對小模型而言：

Skill 是完整食譜，Python Script 是預先準備好的料理機器。

它最好照順序做，不要自由發揮太多。

GPT-5.6：經驗豐富的主廚

GPT-5.6 比較像一位有經驗的主廚。

你可以只告訴他：

用這塊牛腱、洋蔥和番茄，做一鍋清爽、不辣、適合老人家的牛肉湯。兩小時內完成，不要太鹹。

主廚會自行判斷：

牛肉要切多大
是否需要汆燙
番茄什麼時候放
火候怎麼調
水量是否需要補充
牛肉太硬時要延長多久
洋蔥甜度夠不夠
最後如何修正味道

所以強模型的 Skill 不必寫成每分鐘做什麼，而是寫：

目標：
做出清爽、軟嫩、低鹽的牛肉湯。

限制：
- 不可使用辣椒
- 不可太鹹
- 牛肉必須完全熟
- 兩小時內完成
- 使用現有材料，避免浪費

可用工具：
- 壓力鍋
- 溫度計
- 計時器
- 標準高湯配方

這時 GPT-5.6 可以自由調整做法。

但「自由發揮」不是毫無限制。例如主廚仍不能：

把瓦斯開著離開
使用腐敗食材
隨便加入客人過敏的材料
為了加快速度而忽略食品安全

因此：

強模型需要的不是逐步命令，而是目標、食材、工具、驗收標準與安全底線。

套回你的 Vultr 任務
小模型版本

像給廚房學徒：

1. 執行 check_server.py
2. 確認 RAM 大於 4GB
3. 確認磁碟大於 20GB
4. 執行 install_docker.py
5. 建立 docker-compose.yml
6. 執行 docker compose up -d
7. 執行 ollama pull gemma3:4b
8. 執行 health_check.py
9. 任一步失敗立即停止
GPT-5.6 版本

像交代主廚：

在既有 Ubuntu VPS 上，以 Docker 部署 Ollama，
下載指定模型並完成 API 健康檢查。

必須遵守：
- 不公開 11434 到 Internet
- 不格式化磁碟
- 不刪除既有資料
- 不洩漏 SSH key
- 部署必須可重複執行
- 失敗時保留 log 並安全停止

優先使用現有部署腳本，但可依實際環境修正流程。
一句話總結

小模型需要的是「照著做就不會錯的食譜」；GPT-5.6 需要的是「菜色要求、食材、廚具與食品安全規範」。

Python Script 就像已經調校好的電鍋、壓力鍋和切菜機。即使是頂級主廚，也會使用可靠工具，而不是每次都從磨刀、量水、控制火候重新發明一遍。
