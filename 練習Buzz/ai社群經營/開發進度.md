# 開發進度

最後更新：2026-08-05

## 專案現況

目前主要開發場景為 `奧德塞_木馬裡面`。《木馬裡面》已確立為運行於 Buzz AI、由對話自然運作的多人、多 Agent 開放世界，不是回合制劇本遊戲。

全 Channel 的最高設計準則已記錄於 `核心文件.md`：最重要的是好玩，主要手段是盡可能創造大量且有意義的人類與多 Agent 互動，並讓玩家實際感受到 Buzz 作為多人、多 Agent 共享空間的亮點。

核心定位：

> 主持人點燃世界，但故事由所有參與者共同失控。

## 本次已完成

### 1. 改為自由互動模式

- 移除固定輪次、固定發言順序與每輪必定發生的事件。
- 玩家不必等待主持人點名，可以隨時發言、描述行動或同時 `@` 多名 Agent。
- Agent 不只回應呼叫，也能依個性、祕密與現況主動談話、爭吵、結盟、隱瞞、阻止他人或採取行動。
- 主持人在行動改變世界時更新聲響值、外界反應、角色關係與進城狀態。

### 2. 將固定劇情改為可能局勢

- 原本的三幕與第一幕六個節次已改成可供主持人抽取的「局勢群」與「可能局勢」。
- 局勢可以跳過、重疊、延後、倒轉或被玩家完全改寫。
- 玩家可以放棄進城、破壞原定任務或創造新目標。
- 聲響值、木馬空間與外部敵人是世界規則；三幕架構與事件庫只是主持素材。

## Buzz Channel 布置決策

不要讓五名角色 Agent 全部讀取所有文件，否則每個角色都會知道其他人的祕密、未來事件及可能結局。

資料分成三層：

### 共同世界資料

放在遊戲 Channel 的 Canvas 或置頂訊息，所有玩家與 Agent 都能讀取：

- 遊戲定位與互動規則。
- 木馬空間與聲響值規則。
- 目前可感知的環境與進城狀態。
- 每名角色的公開身分。

### 個別角色資料

放進各 Agent 自己的 persona、system prompt、core memory 或私人設定：

- 該角色的個性與語氣。
- 表面任務。
- 私人祕密與隱藏目的。
- 軟肋、行動傾向及資訊限制。

每名 Agent 只能取得自己的私人資料。

### 主持人資料

只由主持人持有：

- 完整局勢庫與突發事件庫。
- 誰動了門栓、誰正在阻礙進城。
- 尚未發生的外界事件。
- 聲響值幕後判定與可能結局。

## 技術注意事項

- Buzz 中的 Agent 必須先加入 Channel，才能讀寫該 Channel。
- 世界觀上 Agent 可以主動行動，但技術上仍需要 Channel 新訊息、`@mention`、監聽事件或 workflow 才會被喚醒。
- 第一版由主持人透過自然的環境更新與 `@Agent` 喚醒角色。
- 暫時不要讓五名 Agent 對每則訊息全部自動回覆，避免洗版與 Agent 互相觸發無限對話。
- 如果目前只有五個 Agent 名額，五個名額全部作為劇中角色，由人類擔任主持人；不要讓角色兼任全知主持人。
