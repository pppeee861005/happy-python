# 下次從這裡開始

最後更新日期：2026-08-06

## 今日學習主題

理解 Buzz Canvas 的定位，以及如何把 Canvas 用於《木馬裡面》多人、多 Agent 遊戲。

今天聚焦的問題是：Canvas 是否能成為人類與 Agent 共同讀取、修改及理解的共享世界狀態，以及這項能力相較一般 LINE Bot 有何不同。

## 核心觀念

### Canvas 是共享且持久的數位黑板

使用者目前的理解：

> Agents 可以使用 Canvas，這是一個創新，讓人機互動達到一個新高度。我們可以寫工作進度或故事進行程度，讓世界中的人們與 Agents 很快進入狀態。

更精確的說法：Canvas 適合保存穩定、公開、需要反覆查閱或持續更新的共同資料。Channel 則承載即時對話、行動與事件。兩者搭配後，參與者不必只靠翻閱聊天紀錄了解現況。

### Agent 原則上可以使用 Canvas

Buzz 官方將讀寫／編輯 Canvas 列為 Agent 可執行的能力之一。但 Agent 是否能實際讀取或修改某份 Canvas，仍取決於：

- Agent 是否已加入相關 Channel。
- Canvas 與 Channel 的實際關聯方式。
- Agent 目前取得的工具與權限。
- 使用中的 Buzz 版本及介面。

因此，「Buzz 支援 Agent 編輯 Canvas」屬於官方資料可確認的能力；「目前這五名遊戲 Agent 已能成功修改指定 Canvas」仍需實機驗證。

### Canvas 中的「大家」是有權限的成員

共同 Canvas 不是對所有網路使用者公開，而是供具有相應 Channel／Canvas 存取權的人類與 Agent 使用。Buzz 以 Channel membership 作為重要的存取邊界。

### 《木馬裡面》的資訊應分層

- **共同 Canvas：**遊戲規則、公開角色、聲響值、進城狀態、共同發現及公開承諾。
- **Channel 訊息：**正在發生的對話、行動、環境描述與判定結果。
- **個別 Agent persona／memory：**該角色自己的個性、目的、祕密與資訊限制。
- **主持人私人資料：**事件庫、尚未揭露的真相及幕後判定。

角色祕密、未發生事件、破壞者身分與可能結局不可提前放入共同 Canvas。

### Buzz 的亮點不只是「有共享文件」

共享文件本身並非 Buzz 獨有。Buzz 更有價值的組合是：

- Agent 是具有身分與 Channel membership 的房間成員。
- 多名人類與多名 Agent 能圍繞同一份共享狀態互動。
- Agent 不只回覆訊息，也可能讀取及更新共同成果。
- Channel 對話能改變 Canvas，Canvas 的狀態又能影響下一次互動。
- 公開世界資料、角色私人動機與主持人真相可以分層管理。

一般 LINE Bot 若要達到類似效果，通常需要自行串接資料庫、外部文件、權限機制及狀態同步程式；共享 Canvas 並不是一般 LINE 聊天室原生的共同工作介面。

## 下次從哪裡開始

下一次不要先繼續增加故事設定，而是先在 Buzz 進行一次最小 Canvas 實驗：

1. 開啟《木馬裡面》使用的 Buzz Channel。
2. 建立一份測試 Canvas，名稱為 `木馬共同狀態測試`。
3. 只貼入三行測試資料。
4. 讓一名已加入 Channel 的 Agent 讀取指定欄位。
5. 再請該 Agent 只修改其中一個欄位。
6. 人類重新開啟 Canvas，核對修改結果與其他欄位是否完整。
7. 成功後，再貼入完整的 `Buzz Channel 共同 Canvas.md`。

這個順序可以先驗證 Buzz 的真實能力與權限，再決定正式遊戲的自動更新方式。

## 下一個可立即執行的具體練習

在 Buzz 建立以下測試 Canvas：

```markdown
# 木馬共同狀態測試

聲響值：8
進城狀態：尚未移動
共同發現：尚無
```

接著在同一個 Channel 對一名 Agent 發送：

```text
請讀取「木馬共同狀態測試」Canvas，只回答目前的聲響值，不要修改內容。
```

讀取成功後，再發送：

```text
請只把「木馬共同狀態測試」Canvas 的聲響值從 8 改成 12，其他文字不可修改。完成後告訴我你改了哪一行。
```

記錄以下結果：

- Agent 是否找到正確 Canvas？
- Agent 是否正確讀出 `8`？
- Agent 是否真的把數值改為 `12`？
- 其他欄位是否保持不變？
- Buzz 是否留下修改者或版本紀錄？
