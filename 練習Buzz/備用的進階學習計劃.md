# Buzz 十天學習計劃

## 學習目標

用每天 1 小時了解 Buzz 的用途、操作方式與核心架構，最後能在 Windows 上使用 Buzz，並判斷是否需要建立完整的原始碼開發環境。

Buzz 是 Block 開源的自架式協作平台，讓人類與 Codex、Claude Code、Goose 等 AI Agent 在同一個工作空間交流、修改程式、執行工作流程及保留稽核紀錄。它不是語音轉文字工具。

## 建議環境

- Windows 10/11
- Git for Windows（包含 Git Bash）
- Docker Desktop
- 8 GB 以上 RAM；建議 16 GB
- 若從原始碼建置：Hermit，或 Rust 1.88+、Node.js 24+、pnpm 10+、`just`

完整開發環境不必第一天安裝。先體驗成品，再決定是否 clone，可減少不必要的設定成本。

## 每日安排

### 第 1 天：建立正確認識

- 15 分鐘：閱讀 [官方 README](https://github.com/block/buzz)。
- 25 分鐘：整理 Buzz 解決的問題，以及它與 Slack、GitHub、一般聊天機器人的差異。
- 20 分鐘：在筆記中寫下三個希望用 Buzz 完成的情境。

**成果：** 能用自己的話說明 Buzz 是什麼、不是什麼。

### 第 2 天：安裝並體驗桌面版

- 15 分鐘：從官方 Releases 下載 Windows `.exe`。
- 25 分鐘：安裝並認識登入、relay、頻道、討論串、私訊及搜尋介面。
- 20 分鐘：記錄可用功能、錯誤與疑問。

**成果：** 完成桌面版安裝；若沒有 relay，先理解連線畫面即可。

### 第 3 天：理解 Nostr 與 relay

- 20 分鐘：理解事件、金鑰、簽章和 relay 的基本概念。
- 20 分鐘：畫出「桌面程式 → relay → 儲存服務」資料流。
- 20 分鐘：理解 Buzz 為何用簽署事件記錄人類與 Agent 的操作。

**成果：** 能解釋 relay 為何是 Buzz 的單一資料來源。

### 第 4 天：閱讀系統架構

- 30 分鐘：閱讀官方 `ARCHITECTURE.md`。
- 20 分鐘：辨認 Rust relay、Tauri/React 桌面端、PostgreSQL、Redis、S3/MinIO 的責任。
- 10 分鐘：補充第 3 天的架構圖。

**成果：** 一張標示主要元件與通訊方式的架構圖。

### 第 5 天：認識 AI Agent 協作

- 20 分鐘：研究 `buzz-cli`、ACP 與 MCP 分別扮演的角色。
- 20 分鐘：理解 Agent 的身分、頻道權限及稽核軌跡。
- 20 分鐘：設計一個 Agent 工作案例，例如問題分類、初步審查或發布摘要。

**成果：** 一份包含輸入、Agent 行動、人工核准與輸出的流程草圖。

### 第 6 天：準備 Windows 開發環境

- 15 分鐘：確認 Git Bash 可執行。
- 20 分鐘：確認 Docker Desktop 正常啟動。
- 15 分鐘：檢查磁碟空間及必要版本。
- 10 分鐘：決定使用 Hermit，或自行管理 Rust、Node.js、pnpm 與 `just`。

**成果：** 開發環境檢查清單。尚未準備修改原始碼者可在此停止安裝。

### 第 7 天：Clone 與初次建置

在 Git Bash 執行：

```bash
git clone https://github.com/block/buzz.git
cd buzz
. ./bin/activate-hermit
just setup
just build
```

記錄下載時間、錯誤訊息與解法。不要提交自動產生的 `.env` 或任何密鑰。

**成果：** 原始碼與依賴準備完成，或留下可重現的失敗紀錄。

### 第 8 天：啟動本機 Buzz

```bash
. ./bin/activate-hermit
just dev
```

- 確認 relay 位於 `ws://localhost:3000`。
- 建立測試頻道、訊息與討論串。
- 觀察桌面程式和 relay 的日誌。

**成果：** 本機 Buzz 成功運行及一張操作截圖。

### 第 9 天：測試與程式碼導覽

```bash
just check
just test-unit
```

- 從 `crates/` 尋找 relay 與核心協定程式碼。
- 從 `desktop/` 尋找 Tauri/React 桌面端。
- 從測試理解一項功能的預期行為。

**成果：** 記錄一條從介面、relay 到資料層的功能路徑。

### 第 10 天：完成小型實驗

從下列項目選一個：

1. 用 `buzz-cli` 讀取或送出測試事件。
2. 修改一段介面文字並重新啟動桌面端。
3. 閱讀一個 YAML workflow，設計簡單的訊息或排程觸發流程。

最後整理：學到的五件事、仍不理解的三件事，以及下一個兩週目標。

**成果：** 可展示的小型實驗與學習回顧。

## 驗收標準

完成計畫後，應能：

- 正確說明 Buzz 的用途與限制。
- 說明桌面端、relay、資料服務及 Agent 之間的關係。
- 使用官方安裝版，或成功在本機啟動開發版本。
- 執行基本檢查與單元測試。
- 提出一個適合自己的 Buzz + AI Agent 使用案例。

## 安全提醒

不要將 `.env`、`BUZZ_PRIVATE_KEY`、API 金鑰或個人測試資料提交至 Git。`just reset` 會清除並重建本機資料，執行前務必確認沒有需要保留的內容。
