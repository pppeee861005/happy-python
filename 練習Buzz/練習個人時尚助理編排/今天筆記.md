### 今天學到的編排觀念

## 「Codex 掛入 Buzz 後能力被封印」的判斷

我的直覺有一部分是對的：這確實可能包含資安與最小權限的設計，但不應直接解讀成 Codex 本身能力變弱。

Agent 在 Buzz 中實際能做什麼，還會受到以下條件影響：

1. **Channel membership：**Agent 只能接觸獲准加入的工作空間。
2. **工具範圍：**Agent 只能使用 Buzz harness 或 MCP 實際提供的工具；沒有提供的電腦、網路或檔案能力不能自行取得。
3. **上下文：**人類在畫面上看到的訊息，不一定全部進入 Agent 當次執行的上下文。
4. **Runtime 設定：**模型、推理強度、逾時、沙箱與工具權限都會影響表現。
5. **協作身分：**Fizz 是 Buzz 中留下操作紀錄的 Agent 身分，Codex 則是背後的執行 runtime；兩者不能完全視為同一層。

所以較精確的說法是：

> Buzz 不是單純把 Codex 的全部能力搬進聊天室，而是把 Codex 放進具有身分、工具、上下文、頻道權限及稽核紀錄的受控工作環境。

這種限制一部分是資安考量，一部分則是工具整合、上下文傳遞與 runtime 設定造成的能力邊界。
