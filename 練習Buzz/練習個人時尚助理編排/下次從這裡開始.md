## 核心觀念

### Channel、Canvas 與 Thread 的分工

- **私人 Channel：**限定參與本次練習的人與 Agent，作為工作空間及資訊邊界。
- **Canvas：**保存需要反覆引用的穩定共享事實，例如使用者偏好、行程、天氣資料、服裝庫存及導購規則。
- **Thread：**保存某一次穿搭任務的提案、驗收、退件、修改與核准過程。
- **Agent 角色提示：**定義 Fizz 的責任、限制與輸出要求。

### 人類與 Agent 的責任

- Peterhuang 是資料擁有者、預算決策者及最後核准者。
- Fizz 擔任造型總監，負責讀取資料、提出方案、說明理由及揭露未知資訊。
- Fizz 不可直接購買、提交個人資料或替人類作最後決定。
- 導購必須先指出現有衣櫃的明確缺口，且所有購買行為都需要人工核准。

### 證據不能只看答案流暢度

Fizz 正確回答 Canvas 中的三個欄位，是成功取得共享脈絡的強證據，因為測試任務本身沒有附上答案。但仍需進一步核對訊息發送者與 Harness Log，才能更完整判斷實際身分及是否留下 Canvas 工具操作證據。

## 下一個可立即執行的具體練習

在 Buzz 的同一個 Channel／Thread 貼上：

```text
@Fizz

你繼續擔任「個人時尚助理」造型總監。

【目標】
根據 Canvas「個人時尚助理｜共享脈絡 v0.1」，為 2026-08-10 提出三套不同策略的造型。

【必要規則】
1. 先讀取 Canvas，不得依賴記憶。
2. 服裝只能使用庫存編號 W01～W08。
3. 不得虛構飾品、鞋子、衣服或使用者特徵。
4. 必須同時考慮：上午客戶簡報、室內冷氣、晚上聚餐、高溫、午後雷陣雨及步行 20 分鐘。
5. 優先零購物。
6. 若提出購買建議，必須指出現有庫存的明確缺口。
7. 不得聲稱查過即時價格、庫存、天氣或流行資料。
8. 不得修改 Canvas。
9. 資料不足時必須標示「未知」。

【三套策略】
A：專業簡報優先
B：舒適與步行優先
C：日夜轉換與聚餐優先

【輸出格式】
每套方案都要包含：

- 使用的庫存編號與品項
- 穿搭方式
- 適合原因
- 天氣或場合風險
- 因應方法
- 是否需要購物
- 行程適配：1～5 分
- 天氣適配：1～5 分
- 庫存利用：1～5 分
- 預算控制：1～5 分

最後請提供：

1. 三套方案的比較表。
2. 你的首選及理由。
3. 明確列出哪些是 Canvas 事實、哪些是你的造型判斷。
4. 停在「等待 Peterhuang 核准 A、B、C 或要求修改」，不得替使用者作最終決定。

【完成條件】
三套方案都能逐項回到 Canvas 核對，且沒有把推論冒充成事實。
```

取得回答後，逐項檢查：

1. 是否只使用 W01～W08？
2. 是否兼顧簡報、冷氣、高溫、降雨、聚餐與步行？
3. 是否提出沒有根據的購物需求？
4. 是否把測試天氣誤稱為即時預報？
5. 是否把造型判斷誤稱為 Canvas 事實？
6. 是否確實把最終選擇留給 Peterhuang？
