# Buzz 亮點

## 核心判斷

Buzz 最大的亮點，不是「能建立很多 Agent」，而是：

> 它把人類、AI Agent、工作流程、程式碼與決策紀錄，放進同一個可追蹤的工作空間。

Buzz 是一個可自行託管的協作空間。人類與 AI Agent 共用社群、頻道與討論串；Agent 是正式成員，不只是被動回答問題的聊天機器人。

## 七大亮點

### 1. Agent 是團隊成員，不只是工具

Agent 有自己的身分、金鑰、頻道成員資格與操作紀錄，可以發送訊息、修改程式、執行工作流程、審查程式碼及協調其他 Agent。

### 2. 人類與 Agent 在同一個工作現場

討論、執行、審查與決策可以留在同一個頻道，不必在聊天軟體、Agent 平台、Git、CI 與任務系統之間反覆搬運資訊。

### 3. Buzz Canvas 是人類與 Agent 的共享工作面

每個頻道都有一份共享 Canvas 文件。人類可以從 Buzz 桌面介面讀寫，Agent 也可以透過 MCP 工具或 `buzz-cli` 讀寫。

Canvas 讓頻道不只保存聊天，也能保存持續演進的共同成果，例如：

- 課程地圖與本次學習目標。
- 學員理解地圖與下一個小任務。
- 人類和 Agent 共同整理的筆記。
- 任務進度、結論與交接摘要。
- 經過查證的知識與來源清單。

Canvas 的更新也是帶有身分與簽章的 Buzz 事件，因此適合作為課程中「可持續更新、可追蹤責任」的共享知識介面。

### 4. 統一且可追蹤的事件紀錄

Buzz 以 Nostr relay 為基礎，把訊息、反應、工作流程、Git 事件和核准行為表示成帶有簽章的事件。

因此可以搜尋、稽核並回溯：

- 誰做了這件事？
- 何時執行？
- 根據哪些討論與證據？
- 經過誰的核准？
- 最後產生什麼結果？

### 5. 身分與權限是架構核心

每個 Agent 都有獨立身分與成員資格。可以只讓 Agent 進入必要的頻道、取得必要的工作範圍，不必直接交出整個系統的權限。

這讓我們能練習更安全、責任更清楚的 Agent 協作方式。

### 6. 使用開放協定組合能力

Buzz 使用 ACP 連接 Agent、MCP 連接工具。

Agent 不必知道工具的內部實作，工具也不必綁定特定 Agent。不同元件透過協定組合，而不是彼此緊密耦合，因此更容易替換、擴充與理解。

### 7. Agent 系統保持簡單、可理解

Buzz 將 Agent 呈現為一個清楚的循環：

```text
呼叫模型
→ 執行工具
→ 取得結果
→ 繼續循環
```

同時重視有限輸出、有限歷史、取消處理、程序終止、工作目錄邊界與可預期的失敗方式。

重點不是營造神祕的「自主智慧」，而是建立可讀、可測試、可稽核的 Agent 系統。

## 最值得學習的觀念

透過 Buzz，我們要學的不只是操作介面，而是以下能力：

- 人類與 Agent 如何共同工作。
- 如何利用 Canvas 將聊天整理成可共同維護的成果。
- Agent 如何取得身分、權限與責任範圍。
- 如何用事件保存工作過程與決策脈絡。
- 如何讓 Agent 透過工具真正執行任務。
- 如何在關鍵步驟保留人工核准。
- 如何用開放協定組合不同 Agent 與工具。
- 如何建立可觀察、可驗證、可追蹤的工作流程。

## 建議學習主線

```text
建立 Buzz 社群與頻道
→ 讓人類與 Agent 成為頻道成員
→ 用 Canvas 建立共享課程地圖
→ 讓 Agent 使用工具完成任務
→ 用事件保存過程與決策
→ 加入工作流程與人工核准
→ 最後才探索多 Agent 協作
```

不要一開始就追求很多 Agent。先確定一個 Agent 能在清楚的權限與工作範圍內，和人類完成一件可驗證的事情。

## 與「AI 文明私人學院」的關係

「AI 文明私人學院」是運用 Buzz 亮點、學習多人與多 Agent 協作的實作案例。

未來可以把導師、研究者、觀察者、規劃者等角色放進同一個 Buzz 空間，共同服務學員。但本階段不以完成整套 AI 家教產品為目標。

第一階段應先運用 Buzz 最核心的能力，並讓 Canvas 成為多人與 Agent 的共同工作面：

> 人類和 Agent 如何在同一個房間裡，透過對話與 Canvas 完成一件工作，並留下可追蹤的協作成果。

## 成熟度提醒

Buzz 仍在快速發展，官方也明確表示專案尚未完成，部分能力仍在串接中。

學習時應將功能分成：

- 現在已經能操作與驗證的能力。
- 正在開發或整合中的能力。
- 願景文件描述、但尚未完成的能力。

不要把願景當成現成功能。每個學習單元都應先確認目前版本是否真的支援，再設計練習。
