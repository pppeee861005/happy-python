# 0 人公司：用 Buzz 實踐的新型企業概念

## 一個正在成形的新物種

「0 人公司」不是完全排除人類，也不是一家永遠沒有老闆、顧客或專家的公司。

它指的是：公司不需要傳統的全職人力編制，日常工作主要由多個 AI Agent 自動協作，人類只在創辦、授權、監督、審核及承擔責任等關鍵位置參與。

Buzz 的 Channel，可能成為這種公司的辦公室、服務櫃台與工作紀錄中心。

> 一個 Channel，就是一間可以運作的微型公司；一群 Agent，就是它的數位團隊。

## 為什麼 Buzz 適合建立 0 人公司

一般 AI 對話通常只有一位使用者和一個模型。Buzz 則可以把不同專長的 Agent、人類專家、顧客及完整討論脈絡放進同一個工作空間。

在這個結構中：

- Community 是企業或服務平台。
- Channel 是一家公司、部門或長期服務項目。
- Message 是顧客提出的一件新委託。
- Thread 是該委託從分析、追問、修正到交付的完整工作紀錄。
- DM 是涉及個資、付款或機密內容的私人溝通。
- Agent 是負責不同職能的數位員工。
- 人類是創辦人、監督者、專業覆核者或顧客。

## 0 人公司的基本結構

```text
Community：AI 服務市集
└── Channel：#都更顧問公司
    ├── @需求訪談Agent
    ├── @營建成本Agent
    ├── @土地法規Agent
    ├── @財務試算Agent
    ├── @風險審查Agent
    ├── @報告統整Agent
    └── 人類專家：必要時進行最終覆核
```

顧客只需要提出問題，不必了解背後用了多少模型或工具。Agent 團隊會分工、互相質疑、交叉檢查，最後交付一份統整結果。

## 一件委託如何完成

```text
顧客在 Channel 發布新 Message
        ↓
需求訪談 Agent 確認資料是否完整
        ↓
多個專業 Agent 平行分析
        ↓
風險審查 Agent 找出矛盾與缺漏
        ↓
報告統整 Agent 產生成果
        ↓
高風險案件交由人類專家覆核
        ↓
在同一個 Thread 中完成交付與修正
```

Thread 不只是聊天紀錄，也是每件工作的可追溯檔案。未來若產生爭議，可以回頭檢查資料來源、推理過程、修改要求與核准者。

## 可以出現的 0 人公司

### 都更初步評估公司

- 試算營建成本。
- 整理基地與建物條件。
- 比較不同設計方案。
- 提醒可能涉及的法規與財務風險。
- 產出供專業人士覆核的初步報告。

### 美股研究公司

- 蒐集公開財報與公司資訊。
- 分析產業、競爭者及風險。
- 分別提出多頭與空頭觀點。
- 比較估值假設。
- 產生研究摘要，但不保證獲利或取代持牌顧問。

### 小型企業顧問公司

- 分析商業模式。
- 估算成本與收入。
- 撰寫行銷文案。
- 研究競爭者。
- 建立執行計畫與每週追蹤報告。

### 內容製作公司

- 研究主題。
- 規劃系列內容。
- 撰寫初稿。
- 進行事實查核與編輯。
- 製作不同平台使用的版本。

## 商業模式

0 人公司販售的不是某一個 Agent，而是一套能完成結果的協作流程。

服務可以分為：

1. 免費體驗：單一 Agent 提供簡單回答。
2. 基礎服務：多 Agent 分工完成初步分析。
3. 進階服務：加入交叉辯論、風險檢查及正式報告。
4. 專業服務：由合格人類專家進行最終覆核。
5. 訂閱服務：按月提供固定額度、持續監測或定期報告。

付款方式可以是一般貨幣、點數、會員方案，也可能使用虛擬貨幣。但虛擬貨幣只是交易工具，真正的商品是可信任、可重複執行的多 Agent 服務。

## 0 人不等於 0 責任

這個概念最大的挑戰，不是 Agent 能不能工作，而是權限、信任與責任如何設計。

必須回答：

- 誰可以向 Agent 下達指令？
- Agent 可以讀取哪些檔案與資料？
- 哪些操作需要人類批准？
- Agent 犯錯時由誰負責？
- 顧客的個資與商業機密如何保護？
- 財務、法律、醫療等高風險建議由誰覆核？
- 如何阻止其他 Channel 成員利用 Agent 操作主人的電腦？

因此，公開服務 Agent 與能操作本機的 Agent 應該分開：

```text
公開服務 Agent
├── 僅能處理公開或顧客授權的資料
├── 不可任意讀取經營者的本機檔案
└── 不可執行高風險系統操作

私人營運 Agent
├── 只存在於受控的私人 Channel
├── 僅開放指定工作資料夾
├── 重要寫入、刪除與外部操作需要批准
└── 保留完整操作紀錄
```

## 最小可行原型

第一個原型可以從「都更成本初步評估」開始，但不要一開始就宣稱能取代完整的都更顧問服務。

### 建議配置

- 一個私人測試 Channel。
- 三個 Agent：需求訪談、成本試算、風險檢查。
- 一個統整 Agent。
- 一份固定的輸入表格。
- 一份固定格式的輸出報告。
- 所有重要結論由人類確認後才能交付。

### 第一階段驗證問題

- 顧客是否能輕鬆說明需求？
- 不同 Agent 是否真的帶來比單一 Agent 更好的結果？
- Agent 之間是否會重複工作或互相矛盾？
- 報告是否能替使用者節省時間？
- 使用者願意為哪一部分付費？
- 哪些步驟一定需要人類專家？

## 真正革命性的地方

傳統軟體把功能做成按鈕；0 人公司把專業角色、工作流程與服務承諾做成一支可被呼叫的團隊。

傳統公司先招募人員，再建立組織；0 人公司可以先設計 Agent、權限與流程，需要時才邀請人類進入關鍵位置。

未來，一個人可能同時創辦及管理許多微型公司。每家公司都有不同的 Agent 團隊、知識、顧客與收費模式，並且全天候運作。

> Buzz 打開的可能不只是 Multi-Agent 聊天生態，而是一個「AI 團隊即服務」的市場。

## 最後的想像

0 人公司不是沒有人，而是把人的價值從重複執行，提升到目標設定、信任建立、創造判斷、專業覆核與責任承擔。

它的雛形可能非常簡單：一個 Channel、幾個 Agent，以及第一位願意提出真實問題的顧客。

但當這套結構可以被複製、計價、稽核並持續改善時，一間新的公司就誕生了。
